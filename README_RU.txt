RU Max Clean — публичный релиз v1.0, builder-база 4.9.1

Это репозиторий программы-сборщика большого русско-русского словаря для
литературного чтения. Готовые бинарные словари в GitHub Releases не публикуются:
они собираются локально под выбранные источники и читательские слои.

В 4.9 добавлены независимые читательские companion-слои: латинские выражения,
архаическая/церковнославянская лексика и фразеология. Они собираются отдельным
скриптом и не раздувают основной русский словарь. Подробности — в
READER_LAYERS_RU.md.

В 4.8.4 сохранены исправления трёх эксплуатационных проблем: пункт 1 больше не падает на
старом имени OpenCorpora, пункт 6 восстанавливает готовый StarDict без исходных
дампов, а загрузчик повторяет временные 429/5xx и держит не более четырёх
соединений. Во время долгих задач лаунчер печатает heartbeat каждые 15 секунд.

4.8 продолжает консервативную meaning-only очистку: переводит безопасные конструкции «О/Об + существительное» в прямые определения, лучше интегрирует скобочный контекст, уменьшает остаточные текстовые редиректы и сжимает датированную энциклопедичность Wikipedia. Дорогие исходные слои по-прежнему переиспользуются из stage-cache.


Что это
-------
RU Max Clean — большой русско-русский офлайн-словарь StarDict для KOReader.
Главное правило проекта: в карточке показывается только значение. Этимология,
произношение, грамматические form-of записи, примеры, названия источников,
служебные пометы и прочий словарный метатекст не должны занимать popup.
Словоформы и варианты написания используются как скрытые поисковые ключи.

MAX-источники
-------------
* Russian Wiktionary / Kaikki — основной лексический слой;
* Wikidata Lexemes — дополнительные русские формы и часть определений;
* В. И. Даль — fallback для старой и редкой лексики;
* Russian Wikipedia — фильтрованный fallback для научной, инженерной,
  медицинской, юридической и другой профессиональной терминологии;
* OpenCorpora — дополнительная морфология, когда сервер доступен;
* extras/ — пользовательские TSV/JSONL-слои.

Быстрый запуск Windows
----------------------
Запускайте один файл:

    RU-Max-Clean.cmd

Меню:

  1. Умная MAX-сборка
     Проверяет обновления, при необходимости скачивает только изменившиеся
     источники и собирает полный словарь. Если ничего не изменилось, Smart Build
     может ограничиться проверкой уже готового StarDict.

  2. Лексическая сборка
     Wiktionary + Wikidata + Даль + OpenCorpora, без Wikipedia.

  3. Офлайн MAX-сборка
     Не обращается в сеть; использует только sources/.

  4. Проверить и скачать обновления источников
     Не пересобирает словарь.

  5. Проверить существующий словарь
     Строгая проверка StarDict и правила «только значение».

  6. Быстрая MAX-пересборка из кэшей
     При наличии исходников запускает signature-aware pipeline и применяет
     текущие правила качества к совместимому stage-cache. Если оставлен только
     готовый StarDict artifact-cache, восстанавливает его напрямую без дампов.

  7. Диагностика компонентов, железа и кэшей

  8. Полностью пересоздать кэши этапов
     Медленный контрольный режим. Нужен только для диагностики или намеренной
     полной переработки источников.

  9. Тест скорости gzip/bzip2 на ваших исходниках
     Локальный benchmark на кэшированных Kaikki/Wikidata. Исходники не меняет.

  0. Выход

Автоматическая подготовка компьютера
------------------------------------
RU-Max-Clean.cmd ищет 64-битный Python 3.10+. Если Python отсутствует и доступен
winget, лаунчер пытается установить его автоматически.

При онлайн-запуске bootstrap.py проверяет/устанавливает ускорители:

    orjson          быстрый JSON parser;
    lxml            быстрый XML parser;
    psutil          диагностика железа/приоритет процесса;
    rapidgzip       многопоточное чтение .gz, в частности Kaikki;
    indexed_bzip2   многопоточное чтение .bz2, если для текущего Python
                    доступен готовый совместимый модуль.

Если опциональный ускоритель поставить нельзя, builder продолжает работу через
стандартную библиотеку Python. На Windows launcher предпочитает уже установленный
Python 3.13 перед 3.14, поскольку для некоторых нативных bzip2-модулей бинарная
поддержка новых версий CPython может появляться позже.

Архитектура ускорения 4.8
-------------------------
4.8 не пытается каждый раз заново переработать гигабайты исходников. Pipeline:

Ключевой performance-path 4.8: semantic-clean больше не прогоняет дорогие регулярные
правила по всем ~600 тыс. определений. SQLite сначала выбирает только кандидатов
(Википедия/Даль/исторические слои, короткие заглушки, скобки, ссылки, URL,
подозрительные хвосты), а затем они очищаются несколькими процессами CPU.
Quality audit также получил быстрый hot-path без компиляции regex на каждую строку.

    Wiktionary + Wikidata + Даль
                |
            lexical cache
                |
            Wikipedia
                |
              max cache
                |
       semantic quality clean
                |
             clean cache
                |
       resolve forms / aliases
                |
          resolved cache
                |
        display-form quality
                |
             form cache
                |
        Quality audit / export
                |
       final StarDict artifact

Stage-cache находится в:

    sources/stage-cache/

Финальный artifact-cache находится в:

    sources/artifact-cache/

Кэш готового StarDict отделён от кэша смысловой базы. Если определения, формы и
правила экспорта не изменились, повторная принудительная сборка сначала проверяет
именно final artifact-cache — ещё ДО открытия/копирования гигабайтного SQLite
stage-cache. Совместимый .ifo/.idx/.dict и QA-отчёты восстанавливаются напрямую,
поэтому не выполняются resolve, quality audit и повторная запись миллионов ключей.

Кэши инвалидируются не по одному общему номеру программы, а по fingerprints
источников и версиям правил конкретных стадий. Поэтому изменение GUI не должно
заставлять перечитывать Wikipedia. Изменение только semantic-clean пересчитывает
очистку и последующие стадии, но может использовать старый max cache.

Wikipedia имеет ещё один подготовленный кэш:

    sources/ruwiki-prepared-v1.sqlite3

Он позволяет не сканировать заново весь многогигабайтный XML.bz2 при обычных
пересборках. Очистка подготовленных кандидатов в 4.8 выполняется
несколькими worker-процессами; число процессов выбирается автоматически и может
быть переопределено переменной RU_MAX_WIKI_WORKERS.

Kaikki и Wikidata сначала проходят дешёвый byte-prefilter: полноценный JSON parser
не запускается для заведомо нецелевых языков/лексем. Для gzip используется
rapidgzip со всеми доступными CPU-потоками, когда модуль установлен. Для bzip2
используется indexed_bzip2 с явно заданным количеством worker-потоков, когда он
доступен; иначе остаётся безопасный stdlib fallback. Большие сетевые файлы по
возможности скачиваются несколькими HTTP Range-соединениями.

Экспорт StarDict 4.8
--------------------
Экспортёр переработан для базы с миллионами ключей:
* offsets канонических статей держатся в памяти, без обратной записи в SQLite;
* links читаются последовательным потоком по первичному ключу;
* display-overrides сливаются в Python без отдельного SQL на каждый ключ;
* неоднозначные статьи собираются из уже подготовленных текстов;
* .idx пишется крупными буферами, а не миллионами мелких write().

Формат StarDict не изменён и остаётся совместимым с KOReader.

Quality pipeline 4.8
--------------------
После импорта всех источников выполняется отдельная активная семантическая стадия.
В отличие от QUALITY_REPORT она действительно исправляет базу, но правила намеренно
консервативны: лучше оставить редкий подозрительный случай для QA, чем удалить
правильное значение.

Стадия умеет, в частности:
* удалять хвосты с примерами ◆/◇, НКРЯ и служебные citation markers;
* удалять уверенно распознанные начальные этимологические, языковые, отраслевые и
  грамматические скобки, не трогая смысловые уточнения;
* превращать безопасные однословные текстовые редиректы/старые написания в скрытые
  aliases вместо показа «Европа» как определения слова «Єѵрѡпа»;
* удалять служебные заглушки «Сокр.», «Аббр.» и явно оборванные «Город в»;
* не допускать грамматически неверного удаления связки «является»/«представляет
  собой» — такие конструкции не обрезаются вслепую;
* нормализовать старые Dal-ключи с POS-мусором вроде «азбука ж» и соблюдать
  fallback-приоритет относительно Wiktionary даже при загрузке старого 4.4 cache;
* обрезать уверенно распознанные склеенные соседние/производные статьи Даля;
* убирать энциклопедический Wikipedia-шум: отдельные спортивные события, сезоны,
  медиа-произведения, группы, команды, некоторые организации/именованные сущности;
* убирать лишние последующие предложения Wikipedia и, только при достаточном
  самодостаточном определении, датированные хвосты создания/принятия/выпуска;
* схлопывать дубли после нормализации;
* после основной очистки формировать небольшой список действительно потерянных или
  объективно слабых Wiktionary/Wikidata-значений и точечно искать для них лучший
  exact-title fallback в подготовленном кэше Wikipedia. Полный дамп при этом не
  перечитывается, а неоднозначные parenthesized titles не создают новые значения
  без достаточных оснований.

Строгий validator 4.8 дополнительно блокирует очевидный non-meaning residue:
form-of строки, usage/domain labels, ◆/НКРЯ/wiki-разметку, служебные заглушки и
оборванные определения.

QUALITY_REPORT
--------------
После MAX-сборки создаются:

    RU-Max-Clean/QUALITY_REPORT.json
    RU-Max-Clean/QUALITY_REPORT.txt
    RU-Max-Clean/QUALITY_REVIEW.tsv
    RU-Max-Clean/QUALITY_ONOMASTICS.tsv
    RU-Max-Clean/QUALITY_CONCISE.tsv

QUALITY_REVIEW.tsv — очередь до 5 000 действительно подозрительных статей с баллом,
причиной, словом, источником и текущим определением. В 4.5 эта очередь почти целиком
забивалась корректными короткими строками вроде «Мужское имя», «Русская фамилия»
и «Река в России». 4.8 сохраняет такие значения в словаре, но выносит их в
QUALITY_ONOMASTICS.tsv. Короткие нормальные значения/синонимы вроде «Церковь» или
«Ангел во плоти» аналогично уходят в QUALITY_CONCISE.tsv. Поэтому основной review
теперь показывает реальный мусор: оборванные фрагменты, URL, неразрешённые redirects,
скобочные пометы, самоссылки, чрезмерно длинные статьи и т.п.

Предупреждения являются QA-кандидатами, а не командами на автоматическое удаление.
Это принципиально: статистика не должна ухудшать реальное покрытие словаря.

Машинная статистика и timings:

    RU-Max-Clean/BUILD_STATS.json
    RU-Max-Clean/BUILD_INFO.json

В консоли выводятся русские выровненные секции и progress bars; JSON-структуры
оставлены в файлах для диагностики.

Обновления источников
---------------------
Состояние сетевых источников хранится в:

    sources/source_manifest.json

Проверяются ETag, Last-Modified и Content-Length; для скачанного файла сохраняется
SHA-256. Новый файл сначала пишется во временный .part и атомарно заменяет старый
только после успешной загрузки. При временной недоступности сервера уже имеющийся
кэш не удаляется.

OpenCorpora остаётся необязательным слоем: его недоступность не должна останавливать
MAX-сборку. 4.8 пробует оба официальных host-варианта opencorpora.org и
www.opencorpora.org перед тем, как пропустить слой.

Переход с 4.6
--------------
Распакуйте 4.8 поверх существующей папки builder, но СОХРАНИТЕ каталог sources/.
Особенно важны уже созданные:

    sources/stage-cache/
    sources/artifact-cache/
    sources/ruwiki-prepared-v1.sqlite3
    sources/source_manifest.json

4.8 совместим с max-cache 4.6: многогигабайтные Wiktionary/Wikidata/Wikipedia
перечитывать не требуется. Из-за новой версии semantic-clean старые clean/resolved/
form/artifact будут пересозданы один раз. Для первого запуска после обновления
выберите пункт 6 «Быстрая MAX-пересборка из кэшей». Второй неизменный пункт 6
должен восстанавливать готовый StarDict artifact напрямую.

Quality Core 4.8 специально исправляет остатки, выявленные реальным 4.6 QA:
* явные «То же, что…», «К …», «Гипокор. к …», «Уменьш. к …» и исторические
  «Вариант X» превращаются в скрытые связи даже если у headword есть другие senses;
* нормальная фраза «Вариант кодирования …» не считается redirect;
* отбор кириллических relation-смыслов больше не зависит от ASCII-only SQLite lower();
* короткие «О рисе», «О Кубе» и подобные определения по возможности разрешаются
  через уже построенный морфологический граф, без угадывания русских падежей;
* если redirect-цель отсутствует, но после «То же, что …» остаётся самостоятельное
  определение, оно сохраняется как прямой смысл вместо метатекста;
* внутренние номера senses [1]/[2] удаляются из видимой карточки;
* начальные скобки очищаются шире, но зависимые конструкции не ломаются ради чистоты;
* длинные fallback-статьи Даля (>520 символов) компактируются только по законченным
  смысловым границам: сохраняется определительное ядро и уверенные региональные
  secondary senses, примеры/пословицы/производные отсекаются;
* для именованных технических моделей Wikipedia датированная история выпуска может
  быть удалена до компактного класса «Суперкомпьютер.», «Кроссовер.» и т. п.;
* QA больше не считает аббревиатуру WWW обычным URL.

Сохранена защита 4.6 от старой регрессии: обычное однословное современное значение
не превращается в alias автоматически. «Абаза → Фамилия» остаётся значением, а
историческое «Єѵрѡпа → Европа» может быть скрытым redirect на современную статью.

---------
После успешной сборки:

    RU-Max-Clean/ru-max-clean.ifo
    RU-Max-Clean/ru-max-clean.idx
    RU-Max-Clean/ru-max-clean.dict
    RU-Max-Clean/BUILD_INFO.json
    RU-Max-Clean/BUILD_STATS.json
    RU-Max-Clean/QUALITY_REPORT.json
    RU-Max-Clean/QUALITY_REPORT.txt
    RU-Max-Clean/QUALITY_REVIEW.tsv
    RU-Max-Clean/QUALITY_ONOMASTICS.tsv

Скопируйте всю RU-Max-Clean в:

    koreader/data/dict/

Для скрытия строки «(запрос: ...)» в KOReader используйте:

    koreader_patch/2-ru-max-clean-meaning-only.lua

Если koreader/patches/ отсутствует, папку можно создать вручную.

Логи
----
MAX:     build.log
Lexical: build_lexical.log

При ошибке достаточно прислать соответствующий log и QUALITY_REPORT.json/txt. Для следующего массового quality-pass особенно полезны QUALITY_REVIEW.tsv и QUALITY_REPORT.json.
