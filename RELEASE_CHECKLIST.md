# Release checklist

1. Запустить полный production build на source-complete наборах.
2. Проверить `QUALITY_REPORT.json`, отсутствие `bad_residue` и `grammar_residue`.
3. Запустить `validate_stardict.py` и все локальные тесты.
4. Собрать builder-only архив через `package_builder.py`.
5. Проверить, что архив содержит программу, тесты, документацию и оригинальную
   `test_books/RU-Max-Clean-Dictionary-Test-Book` для проверки читалки; корпусный
   сканер и его отчёты остаются внутренними инструментами.
6. Посчитать SHA-256 и сохранить его в тексте GitHub Release.
7. Создать tag `vX.Y.Z` и опубликовать один builder ZIP как Release asset.
8. В описании Release указать источники, дату дампов, метрики QA и известные
   ограничения. Сами исходные дампы и пользовательские книги не загружать.

Готовые `.dict/.idx/.ifo`, production-архивы, большие кэши, reader-пакеты,
пользовательские книги и корпусные инструменты анализа книг в GitHub Releases
не публикуются. Единственное исключение — небольшая оригинальная тестовая книга
из `test_books/`. GitHub автоматически добавляет архивы исходного кода к каждому
тегу — это нормально и не является готовым словарём.
