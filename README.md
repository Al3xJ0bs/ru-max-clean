# RU Max Clean

**Программа-сборщик большого русско-русского словаря значений для чтения в KOReader.**

RU Max Clean отвечает на простой вопрос: «Что означает это слово?». Он собирает
русское ядро из открытых лексикографических источников, связывает словоформы с
основной статьёй и очищает карточки от служебной разметки, ссылочных хвостов и
лишней энциклопедичности. На выходе получается обычный совместимый со StarDict
словарь, который можно открыть в KOReader.

Узкие области не смешиваются с русским ядром: латынь, французская лексика,
архаика, литературные имена, фэнтезийные термины, сокращения изданий и
фразеология собираются как отдельные подключаемые слои.

## Как пользоваться

1. Откройте раздел [Releases](https://github.com/Al3xJ0bs/ru-max-clean/releases) и
   скачайте ZIP последней версии.
2. Распакуйте его в отдельную папку на Windows.
3. Запустите `RU-Max-Clean.cmd`. Если Python 3.10+ ещё не установлен, программа
   предложит установить 64-битную версию через winget.
4. Выберите пункт **«Собрать словарь»**, затем профиль:
   - **MAX** — русское ядро с Wikipedia и всеми доступными источниками;
   - **Компактный** — русское ядро без большой Wikipedia.
5. Выберите дополнительные слои или `0`, если нужен только русский словарь.
   При первом запуске источники скачиваются автоматически; повторные сборки
   используют кэши и значительно быстрее.
6. После успешной сборки скопируйте папку `RU-Max-Clean` в
   `koreader/data/dict/`. Выбранные companion-слои находятся в
   `RU-Reader-Packs`; скопируйте нужные папки туда же.
7. В KOReader откройте **Настройки → Словари** и включите нужные словари.

На экране сборщика всегда указаны публичная версия программы и внутренняя версия
builder-базы. Кнопка быстрой пересборки предназначена для повторного запуска на
машине, где уже сохранены источники и кэши. Готовые бинарные словари, книги,
скачанные дампы и кэши в Releases не выкладываются.

## Что входит в проект

- `build_ru_max_clean.py` — сборка русского ядра;
- `RU-Max-Clean.cmd`, `ru_max_launcher.py` — простой Windows-запуск и меню;
- `build_reader_packs.py`, `reader_packs/` — отдельные литературные и языковые
  слои;
- `validate_stardict.py` — строгая проверка результата;
- `test_*.py` — локальные регрессионные тесты;
- `koreader_patch/` — необязательный Lua-патч для карточек «только значение»;
- `README_RU.txt`, `READER_LAYERS_RU.md` — дополнительные технические сведения.

## Проверка проекта разработчиком

Большие исходные дампы нужны только для production-сборки. Быстрые проверки,
которые не скачивают их:

```text
py -3 -X utf8 test_builder.py
py -3 -X utf8 test_source_manager.py
py -3 -X utf8 test_stage_cache.py
py -3 -X utf8 test_package_builder.py
py -3 -m compileall -q .
```

Проверки reader-слоёв и внутреннего анализа корпуса запускаются только в CI и
исходном репозитории разработчика; `internal_book_coverage.py` и fallback-пакет
для фиксированного корпуса в пользовательский ZIP не входят.

Собрать архив программы вручную:

```text
py -3 -X utf8 package_builder.py
```

Скрипт создаёт builder-only ZIP с `BUILD_MANIFEST.json` и SHA-256. Он исключает
готовые `.dict/.idx/.ifo`, пользовательские книги, production-кэши, большие
дампы и внутренние корпусные отчёты.

## Качество и лицензии

Перед выпуском проходят регрессионные тесты, `compileall` и
`validate_stardict.py`. Код распространяется по MIT; лицензии и требования
атрибуции Wiktionary, Wikidata, Wikipedia, OpenCorpora и Даля указаны в
[`NOTICE_DATA.txt`](NOTICE_DATA.txt).

Ошибки в определениях и редкие слова можно присылать через
[Issues](https://github.com/Al3xJ0bs/ru-max-clean/issues). Готовые словари не
являются частью GitHub-проекта: каждый пользователь собирает их локально под
свои источники и выбранные слои.
