RU Max Clean 1.6.2 — исправление builder-пакета
===============================================

- В builder-only ZIP включён обязательный модуль `dictionary_layout.py`.

RU Max Clean 1.6.1 — производительный сборщик и чистый builder-релиз
=====================================================================

- Устранён критический регресс производительности Windows: rapidgzip больше не
  включается только по факту установки и не ставится автоматически. Надёжный
  stdlib gzip используется по умолчанию; экспериментальный режим доступен
  только через `RU_MAX_ENABLE_RAPIDGZIP=1`.
- Ускорен импорт Kaikki дополнительной отложенной сборкой вторичных SQLite-индексов,
  пакетным слиянием временных таблиц и устранением повторной нормализации ключей.
  Полный локальный прогон на кэшированных источниках сократился до минут вместо
  многочасового ETA при неудачном rapidgzip.
- Ускорен импорт Kaikki: ссылки, значения и морфологические подсказки записываются
  пакетами SQLite вместо отдельной операции на каждую запись.
- Исправлено отображение долгих этапов: heartbeat обновляется на месте, а этапы
  сборки явно показывают запуск и длительность без засорения консоли.
- Загрузчик больших файлов сохраняет успешно полученные диапазоны при HTTP 429,
  использует Retry-After и повторяет только проблемные части.
- Полностью удалён снятый с поддержки внешний морфологический источник; кэш-правила
  подняты до lexical-v2-sources, а устаревшие записи манифеста не попадают в BUILD_INFO.
- В builder-only ZIP добавлена небольшая оригинальная EPUB/FB2 QA-книга; готовые
  словари, пользовательские книги, кэши и production-пакеты по-прежнему исключены.
- README дополнен инструкциями по тестовой книге, KOReader-патчу и политике редких
  значимых релизов.
- Заголовки companion-слоёв в KOReader переведены с технических slug-имён на
  понятные русские названия; имена папок и файлов сохранены для совместимости.

RU Max Clean 1.5.1 — устойчивые загрузки больших источников
=============================================================

- Параллельная загрузка больших дампов теперь ограничена безопасными двумя
  соединениями по умолчанию и автоматически снижает число соединений при HTTP
  429 вместо немедленного перехода на медленную загрузку с нуля.
- Повторяются только неудачные диапазоны; уже загруженные части сохраняются.

RU Max Clean 1.5 — полная корпусная диагностика и Unicode-ключи
=================================================================

- Расширено распознавание ключей на латинские буквы с диакритикой (`è`, `à`,
  `Brüder`), которые встречаются в оригинальных и переводных текстах.
- Добавлен внутренний `internal_book_coverage.py`: он перечисляет каждый
  пропуск фиксированного корпуса и создаёт отдельный fallback-пакет, не меняя
  русское ядро. На полном корпусе из 23 книг такой QA-прогон дал 100,000% и
  0 неизвестных токенов.
- Fallback-пакет намеренно не входит в пользовательский ZIP: для имён,
  авторских форм и иноязычных фрагментов он показывает контекстную помету, а
  не притворяется полноценной словарной статьёй.

RU Max Clean 4.7.0 TURBO QUALITY CORE
========================================

Качество
--------
- Исправлена причина тысяч пропущенных кириллических relation-смыслов: SQLite
  lower() не является Unicode-aware для кириллицы. Candidate SQL теперь явно
  отбирает заглавные и строчные «То же, что…», «К …», «О …», «Вариант …»,
  «Гипокор.», «Уменьш.», «Димин.» и не зависит от ASCII-only lower().
- Новый синтаксический parser различает настоящий historical/variant redirect и
  обычное определение, начинающееся словом «Вариант». Например «Вариант бѹкварь»
  является alias, а «Вариант кодирования цифрового кода…» остаётся определением.
- Explicit relation sense теперь может быть удалён отдельно даже у многозначного
  headword: другие реальные значения сохраняются, а lookup key дополнительно
  указывает на каноническую статью.
- Цель relation разрешается через уже существующий граф lookup-форм и aliases,
  поэтому не требуется угадывать русскую морфологию. Поддерживаются несколько
  целей для гипокористик/вариантов и неоднозначных форм.
- Короткие глоссы «О рисе», «О Кубе», «О Нью-Йорке» по возможности превращаются
  в скрытые aliases через тот же морфологический граф. Безопасные «О том, кто…» /
  «О том, что…» превращаются в прямые определения.
- Если target у «То же, что…» отсутствует, но хвост содержит самостоятельный смысл,
  redirect-метатекст удаляется и остаётся прямое определение.
- Удаляются внутренние номера значений [1], [2] из видимого текста.
- Расширена аккуратная обработка начальных скобок, включая usage-selection,
  иноязычное написание, врождённое/историческое уточнение и «(радио-)…».
  Зависимые фразы не ломаются ради формального удаления скобок.
- Длинные fallback-статьи Даля (>520 символов) компактируются по законченным
  смысловым границам: основное ядро и явно маркированные региональные вторичные
  значения сохраняются, примеры/пословицы/производные хвосты отбрасываются.
- Для именованных технических моделей Wikipedia сильнее удаляется датированная
  история производства/создания, когда перед ней остаётся достаточный класс.
- QA URL detector больше не считает обычное сокращение WWW URL-адресом.

Производительность
------------------
- Сохранены candidate-driven semantic cleanup, multiprocessing, быстрый QA hot-path,
  rapidgzip/indexed_bzip2 и финальный artifact-cache 4.6.
- MAX cache 4.6 совместим с 4.7. При обновлении достаточно пересчитать quality и
  последующие стадии; Kaikki/Wikidata/Dal/Wikipedia заново разбирать не требуется.
- Semantic-clean stage signature обновлена отдельно от source/max stages, поэтому
  инвалидация остаётся точечной.

QA / тесты
-----------
- Добавлены regression tests на реальные остатки 4.6: Base58, исторические варианты,
  «О рисе», multi-sense redirect, БОМЖ fallback, [1]/[2], WWW, ASCI White,
  parenthetical selection и длинные статьи Даля.
- Современные однословные значения «Фамилия»/«Церковь» по-прежнему защищены от
  ошибочного превращения в alias; исторические bare redirects сохранены.

RU Max Clean 4.6.0 TURBO QUALITY REVIEW
==========================================

Качество
--------
- Исправлена важная регрессия 4.5: современное однословное значение больше не
  превращается в redirect только из-за существования одноимённой статьи. Строки
  вроде «Абаза -> Фамилия» и «Божий дом -> Церковь» снова остаются видимыми
  значениями; bare-word aliases разрешены только историческим языковым слоям.
- Явные redirects расширены: «то же, что», «см.», «к», «гипокор. к»,
  «уменьш. к», «димин. к» безопасно становятся скрытыми lookup aliases, если
  целевая статья существует.
- Скобочный культурный/исторический контекст больше не торчит отдельной пометой:
  смысловой контекст переносится в обычную фразу, а чисто отраслевой/грамматический
  контекст удаляется.
- Добавлен разбор вложенных начальных скобок и реальных QA-случаев вроде
  «(Ольги́н (Holguín)) испанская фамилия», старых названий населённых пунктов,
  расшифровок аббревиатур и этимологических/иноязычных написаний.
- Исправляются конструкции вида «Вокульский (фамилия)» -> «Фамилия» и
  «Глава (раздел книги)» -> «Раздел книги».
- Удаляются Wikipedia-списки/дизамбиги, сломанные dangling fragments, URL и
  дополнительные extraction tails; датированная история обрезается только когда
  перед ней остаётся самостоятельный смысл.
- Parenthetical-only темы вроде «(о взятках)» больше не считаются значением.
- Оборванные географические фрагменты расширены до «Провинция в», «Озеро на» и т.п.

QA
--
- QUALITY_REVIEW.tsv теперь действительно actionable: корректные краткие
  «Мужское имя», «Русская фамилия», «Река в России» вынесены в отдельный
  QUALITY_ONOMASTICS.tsv.
- Корректные короткие значения и синонимические глоссы вынесены в
  QUALITY_CONCISE.tsv и не забивают очередь ошибок.
- Даты Wikipedia больше не считаются проблемой сами по себе; warning ставится
  только при наличии признаков энциклопедической истории/производства.
- Добавлены предупреждения unresolved redirect/about-fragment и новые regression
  tests по реальным строкам из QUALITY_REPORT/QUALITY_REVIEW 4.5.

Производительность
------------------
- Semantic cleanup стал candidate-driven: вместо полного последовательного
  прохода по ~600 тыс. статей SQLite предварительно выбирает только потенциально
  изменяемые строки.
- Кандидаты нормализуются пакетами через ProcessPoolExecutor (до 12 процессов);
  изменения SQLite применяются детерминированно в главном процессе.
- QA hot path переработан: дорогие regex вызываются только после дешёвых
  prefilters, не компилируются на каждую строку.
- Сигнатуры semantic-clean/QA изменены, но max cache 4.4/4.5 остаётся совместимым.
  Гигабайтные источники ради перехода на 4.6 перечитывать не требуется.

Интерфейс
---------
- Версия launcher/CMD обновлена до 4.6; Windows launcher по-прежнему предпочитает
  Python 3.13 для готовых wheel rapidgzip/indexed_bzip2.
- Human report показывает число реально проверенных semantic candidates, worker
  processes и отдельные информационные QA-классы.
- Снятый с поддержки внешний морфологический слой удалён из сетевой проверки;
  сборка использует формы и ссылки из актуальных лексических источников.

RU Max Clean 4.5.0 TURBO QUALITY PIPELINE
=========================================

Производительность
------------------
- Final artifact-cache теперь проверяется до восстановления любого SQLite stage-cache.

- Диагностика показывает stage-cache и final artifact-cache.
